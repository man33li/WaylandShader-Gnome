# Plan A — Odin GNOME backend, direct C ABI, existing GTK native chooser

## 1. Summary & key decisions, including rejected alternatives

This is phase 2, not an implementation or a claim of passing tests. The requirements research gate exists (`docs/waterfall/GATES.md:5–6`); implementation and verification remain separate phases (`docs/waterfall/README.md:7–12`). All paths below are repository-relative. Descriptions of new files and commands are design requirements, not observations of files already present. `[INFERENCE]` identifies derived or untested feasibility claims.

**Cut over the GNOME build completely:** three Odin artifacts, `libwaylandshader-gnome.so`, `waylandshader-gnomectl`, and `waylandshader-gnome-controller`. All effect registration, callbacks, rendering, shader loading, client logic, argument parsing, and GUI behavior are Odin. Keep the JavaScript extension, schema, public C introspection header, private patched librashader, and KWin sources. Do not introduce another renderer, protocol, settings version, compatibility shim, or feature. Existing GNOME targets are identified in `gnome/CMakeLists.txt:34–37,59–94,114–123`; KWin also consumes the shared C++ sources (`CMakeLists.txt:25–28,40–48`).

### Resolve the dangerous boundaries first

1. **Exact GObject/Clutter ABI, before rendering:** reproduce the public instance/class prefixes in Odin, prove sizes, alignments and offsets against a C SDK probe at build time, then register the type entirely in Odin. No guessed padding and no runtime C subclass shell. Section 4 specifies the complete layout and signatures.
2. **Real GIR dumper, before shader work:** retain the existing C API header and run the scanner against the real Odin shared library. The scanner executes a linked GType dumper; hand-authoring XML is not a substitute ([scanner documentation](https://gi.readthedocs.io/en/latest/tools/g-ir-scanner.html); `research/odin-native.md:24–27`, relative to `docs/waterfall/01-requirements/`). The first integration gate is constructor → status → shutdown through GJS with the final exported API, not an empty sample library shipped as a component.
3. **Shared EGL contexts and fences, before Clutter painting:** port `ShaderRuntime` nearly algorithm-for-algorithm and run its real-GL regression independently. Use GL sync objects, not EGL fence extensions: the original uses `glFenceSync/glFlush/glWaitSync` (`src/shader_runtime.cpp:530–590`). Keep asynchronous compilation in a separate, shared context and rendering in that context on the compositor thread after the worker relinquishes it.
4. **GUI: direct GTK 3 C API, not Qt, GTK4, or immediate-mode drawing.** GTK3 is already an explicit package dependency and supplies the existing GNOME-native chooser and schema (`gnome/default.nix:30,35,56–61`; `docs/GNOME.md:309,328`). Use `GtkFileChooserNative` with its native GTK dialog/portal behavior, not a custom browser. It defaults to `GtkFileChooserDialog` and can delegate to the desktop portal ([GTK3 documentation](https://docs.gtk.org/gtk3/class.FileChooserNative.html)). Keep `org.gtk.Settings.FileChooser` available and test Open and Cancel in the wrapped installed program. This chooses an already present dependency over the research's otherwise reasonable GTK4 recommendation (`research/odin-control.md:7–13,56–64`).

Rejected alternatives:

- C/C++ implementation of the subclass, Qt controller bridge, or retaining the C++ shader runtime: leaves required components unported. A build-time C ABI probe and C test harness are permitted tooling, not application implementations.
- Generated bindings for all GTK/Mutter, community GTK4 bindings, libadwaita: unnecessary new binding/dependency surface. Bind only C declarations actually used. GTK4 is viable but does not eliminate exact numeric-editor or chooser tests; it adds dependency/wrapping migration without a feature requirement.
- Raylib/microui, SDL, custom file chooser: would require new layout, accessibility, focus and native-dialog infrastructure (`research/odin-control.md:7–13`).
- libdbus/sd-bus: additional event-loop glue; GDBus already shares the GTK/GLib context (`research/odin-control.md:15–25`).
- Rendering inside Mutter's context, CPU waits, synchronous compilation, one chain shared by monitors: changes host-state safety, responsiveness, temporal history or frame cadence (`src/shader_runtime.cpp:166–209,302–458,507–591`).
- General SoA/entity framework: monitor count is small and a selected paint touches most hot fields. A contiguous hot/cold split and index handles suffice. Assume steady-state repaint at each output's own refresh rate, with **zero Odin heap/temp allocations after resource warm-up**, excluding topology/resize/color-state transitions and error reporting. Do not claim zero allocations inside GL drivers, Cogl, or librashader.

No implementation, build, test, or live compositor modification is performed by this design assignment.

## 3. Per-component design and complete feature mapping

The native research summary omits `GError**` from its abbreviated `set_enabled` signature; the actual header (`gnome/native/waylandshader-effect.h:76`) wins.

**JSON/settings home:** `model/json.odin` supplies parsing and deterministic serialization; `native/settings.odin` owns application policy. Status preserves `enabled, active, loading, preset, requestedPreset, recentPresets, error, parameters, outputs`; parameter rows retain `name, description, minimum, maximum, step, default, value`; outputs retain `id, name, shaderEnabled, colorEnabled, gamma, saturation, shaderActive, colorActive`, and `bypass` only if nonempty (`waylandshader-effect.cpp:522–544`). Keep unknown status keys when the client reprints status: store validated raw JSON alongside typed records (`src/controller_client.cpp:349–352`).

Saved document remains `{version:1,enabled,preset,recent_presets,parameters:{preset:{name:value}},outputs:{id:settings}}`. Empty object means defaults; other objects require numeric version exactly 1. Reject import during compile or after fatal renderer failure; validate booleans/numbers/objects and nonempty output/parameter names as the original does. Parameter map preset keys are not additionally restricted: do not invent validation. Missing saved preset remains an asynchronous load failure, not extension-enable failure. Keep initial restored selection in export while reconstruction is pending. Recent entries are advisory: non-array means empty, skip invalid entries, accept absolute case-insensitive `.slangp`, dedupe exact strings on import, retain missing files and cap at ten. Successful canonical-path loads perform MRU/symlink dedupe; failed loads never touch recent history (`waylandshader-effect.cpp:1377–1451,865–868`). Persist disconnected connector profiles and overrides for other presets.

Use `core:encoding/json` dynamic JSON values for trust-boundary parsing, not an unchecked cast directly into typed records. Encode known keys deterministically, sort arbitrary object keys recursively on cold paths, retain array order, emit compact native JSON and four-space CLI JSON with final newline. Compare object semantics in compatibility tests; include stable formatting/string-escaping goldens for CLI output. Qt's lexicographic object iteration is observable (`research/native-effect.md:209–213`); include non-ASCII key ordering/escaping fixtures rather than assuming Odin map order equals Qt.

**Rendering sequence (preserve, do not redesign):**

1. Save raw-GL bindings before effect-owned operations; clear/continue original scene through Cogl, flush it, blit into `raw` FP16 premultiplied surface.
2. Configure target and working color state. Preserve the HDR mastering-headroom equation `working.ref * target.mastering_max / target.ref`; otherwise ordinary sRGB. If unequal, use Mutter's target→working transform into `srgb` FP16. Do not substitute a hand tone mapper (`waylandshader-effect.cpp:285–338`). Working samples are encoded sRGB for the adjustment snippet, not an excuse to omit the sRGB decode/re-encode steps.
3. Copy input level zero into effect-owned full-mip-chain `GL_RGBA16F` source; keep `GL_TEXTURE_MAX_LEVEL=0` after copy. Never change Cogl-owned texture parameters. Patch handles exposure during mip generation (`research/native-effect.md:58,231–234`).
4. For shader-active output, build the fixed-size frame record. Use expected presentation time or monotonic fallback; nominal refresh or one measured warm-up before externally driven view rendering. Counter starts at zero, elapsed milliseconds clamps to u32, and clear-history resets only after successful frame (`waylandshader-effect.cpp:1122–1161`).
5. Runtime renders into FP16 `destination`, fences both directions, restores host. Rebind destination then previous texture to publish cross-context changes even when Cogl caches binds (`waylandshader-effect.cpp:1152–1158`). Retain preceding destination resources while a chain can still reference them; free retired resources only after replacement render or runtime destruction.
6. If target differs or active color adjustments differ from 1/1, use final FP16 surface and original texture-lookup GLSL, byte-for-byte: unpremultiply, gamma on encoded RGB, piecewise sRGB decode, Rec.709 luma saturation, clamp nonnegative, piecewise encode, premultiply; alpha ≤0 writes black. Cache gamma/saturation uniform writes. Mutter handles working→target transform (`waylandshader-effect.cpp:319–336,1166–1180`).
7. Pixel blit result back; check GL error. On failure preserve/restore raw scene and set bypass/error. No CPU readback in production.

### 3.2 Shader runtime

`runtime` preserves every behavior listed in `research/native-effect.md:105–145,149–181`:

- Direct-link the private patched librashader 0.10.1 C ABI 2; use exact header structs/options and by-value image arguments, not older ABI declarations ([migration guide](https://github.com/SnowflakePowered/librashader/blob/v0.10.1/MIGRATION-ABI2.md)). Loader callback is C ABI `eglGetProcAddress`.
- Validate absolute readable file, NUL rejection, duplicate output keys and absent display/context. Native `load_preset` still does **not** impose a suffix rule; only CLI/GUI do (`research/control-surface.md:12,164–165`).
- Per-output chain array `{key:uintptr,chain:opaque pointer}`. Empty inventory still compiles one validation chain to resolve parameters, then frees it. Preset objects, metadata lists, chains, error strings and error handles each have explicit matching frees on all error exits.
- Options preserve original-aspect and frametime uniforms, GL version ×10 GLSL, DSA only at ≥4.5, cache enabled and mipmaps enabled; reject zero active passes (`src/shader_runtime.cpp:348–422`).
- Metadata: finite ordered bounds, nonnegative finite step, in-range finite default/value after f32 conversion, nonempty names; union is last-pass-wins, then sorted. Unknown overrides rejected. All chains must agree on resolved parameter value. Retain NUL-terminated parameter names for C calls (`src/shader_runtime.cpp:372–445`).
- Set parameter: validate finite f64 and representable/in-range f32, early-out on equal f32; preflight old values on all chains; apply all, rollback already changed chains on partial failure, retain old model until success (`src/shader_runtime.cpp:153–164,461–505`).
- Validate frame texture ids are nonzero/distinct, dimensions positive/in bounds, format nonzero, finite positive FPS, frame number fits size_t, original host context is current. Preserve DEFAULT_MVP `{2,0,0,0;0,2,0,0;0,0,0,0;-1,-1,0,1}`, direction 1, no rotation, total/current subframes 1, aspect ratio, FPS, delta and clear-history (`src/shader_runtime.cpp:507–573`).
- Preserve diagnostic extraction/fallback and cleanup warnings. Destruction enters private context; if lost, log and leak GL chain objects rather than freeing them in the compositor context. Destroy only owned context/surface, never terminate the borrowed display (`src/shader_runtime.cpp:35–50,182–209`).

### 3.3 D-Bus client

`client` uses GIO session-bus connection and asynchronous `g_dbus_connection_call`, timeout 10,000ms, typed GVariant construction and explicit finished callbacks. Preserve service `org.gnome.Shell`, path `/WaylandShader`, interface `org.waylandshader.Effect`; methods exactly `status()->(s)`, `loadPreset(s)->(b)`, `setEnabled(b)->(b)`, `setParameter(sd)->(b)`, output shader/color `(sb)->(b)`, gamma/saturation `(sd)->(b)`, and signal `statusChanged(s)` (`extension.js:8–22`). Do not move D-Bus export into the native module.

- Subscribe to effect status, Shell extension lifecycle, and name-owner changes before snapshots; capture `interface_generation` in each effect request. Invalidated responses must not resurrect stale status. Clear status and notify disconnection when owner changes or extension ceases to be active (`src/controller_client.cpp:62–115,364–379`).
- `ensure_available(false)` never enables. Mutation/GUI uses true, probes status first, activates only `waylandshader@man33li.github.com` via existing Shell Extensions path/interface, then watches `ExtensionStateChanged` before `GetExtensionInfo`. Existing numeric states 1 active, 2/6/8 pending and 10s activation deadline are copied from source, not generalized to other GNOME majors (`src/controller_client.cpp:117–215`; `src/controller_backend.h:7–19`).
- Classify missing service/object/method/interface as Unavailable; every `org.waylandshader.Error.*`, **including the JS Unavailable suffix**, as Rejected; other bus failures Transport; malformed tuples/JSON Protocol; false boolean reply Rejected. Preserve existing diagnostics/install hints (`src/controller_client.cpp:21–57`). Do not silently “fix” exit-code behavior during a port.
- Validate complete candidate status before replacing current state: required bool/string/array fields; optional recent array of nonempty strings; unique parameter names/ids, finite bounds/default/value/step, and output range/flag/bypass types. On bad signal, invalidate availability. Retain original JSON object for CLI (`src/controller_client.cpp:229–360`).
- Plain heap request records own callback data, expected generation and cancellation token. Closing client unsubscribes and cancels/drains local callbacks; no callback references a freed window. Cancellation does not imply server mutation cancellation. No automatic reconnect/retry beyond the original explicit activation sequence.

### 3.4 CLI

`ctl/arguments` is a small explicit parser for the existing Qt grammar, not a new command framework. Support `-h`, `--help`, `--timeout SECONDS`/`--timeout=SECONDS`, option terminator `--`, and original command counts; snapshot the baseline help and option/error cases before replacing Qt. No `--version` feature is introduced.

| Commands | Odin behavior |
|---|---|
| `status`, `parameters`, `outputs` | Read-only availability; full JSON object or selected raw array; never activate. |
| `load FILE` | Existing file, case-insensitive `.slangp`, canonicalize; activate if needed, submit then wait for accepted request's compile outcome. A status may precede acceptance: query again after reply. Another request replacing it is failure, not success. |
| `param NAME VALUE` | Nonempty name, full finite-number parse, call parameter setter and request status. |
| `output ID_OR_NAME shader on\|off` / `color on\|off` | Exact id first, otherwise unique exact name; unknown/ambiguous is usage error. Independent flags do not enable master. |
| `output ID_OR_NAME gamma NUMBER` / `saturation NUMBER` | Finite range [0.1,5] / [0,2]; same id selection and status refresh. |
| `enable`, `disable`, `toggle` | All may activate; toggle reads current master state before setter. |

One GLib main loop; overall deadline defaults to 120s, validates integer 1–3600 and starts before availability/activation. Terminal completion happens once. Preserve stdout JSON vs stderr errors and codes **0 success, 1 rejected/shader/replaced load, 2 usage, 3 unavailable/transport/protocol, 4 overall timeout**. Per-call 10s failures remain bus errors, not remapped to overall timeout. Timeout message says mutation may still finish. Original source is the precise oracle (`src/ctl_main.cpp:22–140,142–287`; `research/control-surface.md:72–113`).

**Important numeric-editor decision:** do not assume GtkSpinButton's decimal limit and tiny-delta behavior match Qt's 323-decimal `ParameterSpinBox`. GTK3 uses `MAX_DIGITS=20` and `EPSILON=1e-10` ([GTK spin implementation](https://raw.githubusercontent.com/GNOME/gtk/gtk-3-24/gtk/gtkspinbutton.c)). Use one small composite of native `GtkEntry` and increment/decrement `GtkButton`s for shader parameters only: authoritative f32 model, validated f64 bounds, native focus/label relation, accessible button names, Up/Down and PageUp/PageDown stepping, Enter/focus-out commit, temporarily incomplete numeric input allowed. Invalid/incomplete commit restores last valid value; a valid float never gets decimal-rounded by GTK. Use Odin's shortest float formatting if the pinned revision provides the required round trip; otherwise use GLib ASCII conversion plus the minimum significant-digit round-trip search (1–9 for f32), tested against the baseline, not a locale-sensitive formatter.

### 4.1 Exact GObject layout and registration

### 4.2 Bindings, C ownership, runtime context and errors

- Use `core:c` types for C integers, size_t and bool; GLib gboolean is c.int, librashader C bool is its header's C `_Bool`, not gboolean. Opaque SDK types remain pointers. Mirror `MtkRectangle`, Graphene matrix/alignment and Clutter luminance records only when actually read/passed; measure all of them. Use the correct SIMD alignment for Graphene matrices, not `[16]f32` assumed ABI-compatible.
- Direct-link GLib/GObject/GIO, Mutter/Clutter/Cogl/Graphene, libepoxy and private librashader. libepoxy's GL/EGL entry names are **exported function-pointer variables**, with C header macros mapping `glFoo` to `epoxy_glFoo`; bind those as foreign variables of C-procedure-pointer type, not nonexistent function symbols. This keeps context-sensitive dispatch and epoxy version/extension queries equivalent to the source (`src/shader_runtime.cpp:230–231,341–345`). The probe/link test must exercise the exact chosen binding form. No GL loader writes a process-global function table concurrently on worker and host.
- Every C→Odin entry establishes `context = runtime.default_context()` before context-dependent work; the owned worker does the same. Do not rely on Odin `main` running inside Shell or on inherited allocators (`research/odin-native.md:10–13`). Engine/job memory uses explicit allocators, not temporary allocators crossing callbacks. CLI and GUI initialize their own main context conventionally.
- Use ordinary result/error records, explicit cleanup with `defer`, and checked allocator operations at recoverable boundaries. No `panic`, `assert` on external data, `or_panic`, unchecked map lookup, or bounds failure can cross C. Compile-time `#assert` is encouraged. Runtime impossibilities must return/report an error and continue original scene where safe. Do not “solve” this by disabling Odin bounds checking. There is no claim that Odin can recover from arbitrary memory corruption or the process-wide OOM behavior of GLib.
- C strings returned to GJS use GLib allocation. Copy foreign string data before freeing its owner. Keep source buffers alive during C calls, reject embedded NUL on filesystem paths and C-name boundaries without silently truncating; test Unicode and invalid inputs against the baseline behavior. `GError**` is optional: set via `g_set_error_literal` only under the GLib contract, domain `wayland-shader-error`, code1 (`waylandshader-effect.cpp:1219–1229`).
- Native status construction failure returns the original fixed JSON; settings export failure returns null; constructor failure returns null; mutators return false+GError; paint/attach/idle failures become status errors and pass-through behavior. All void exported shutdown/reset paths remain safe and idempotent as applicable. Error string creation is outside the successful hot path.

### 4.3 EGL sharing, worker publication and destruction

Preserve `CurrentContext` snapshot of display, context, distinct draw/read surfaces and selected API; restore on every exit, including a caller with no current context or a worker initially using another API (`src/shader_runtime.cpp:54–123`). Native HostContext is a separate helper for resource destruction under the borrowed compositor context.

Context creation requires desktop OpenGL EGL. Query host context client type, reject GLES/GLX, bind OpenGL temporarily, choose appropriate EGL config; prefer EGL1.5 or KHR surfaceless, otherwise 1×1 pbuffer. Try GL4.6,4.5,3.3 in that order, each normal then robust/lose-on-reset, sharing the **actual captured** host context. Require GL≥3.3 and texture storage support (GL≥4.2 or extension). No fallback to GLES or unrelated EGL display (`src/shader_runtime.cpp:211–291,341–345`).

One worker at a time, created with GLib `g_thread_try_new` so thread creation failure is recoverable. At launch, deep-copy path/overrides/output keys/generation/display/share context into `Load_Job`; allocate completion GSource on owner thread. Worker touches only its job/runtime, never Engine arrays, GTK, Cogl, or live runtime. It unbinds private context before attaching completion source to owner's captured GMainContext. Completion joins before reading job results, supplies publication ordering, destroys stale results on owner thread, installs matching result, updates MRU/metadata/history and starts the pending request. Shutdown marks stopped and joins before destroying completion or Engine: it never waits for an owner-thread action from the worker. This is the source's existing job/generation algorithm (`waylandshader-effect.cpp:790–921`), not a task pool.

On every frame: host inserts incoming GL sync and flushes; private context server-waits and deletes sync; librashader queues work; private inserts outgoing sync and flushes even when rendering reports failure; restore exact host then server-wait/delete outgoing. Never substitute CPU wait or `glFinish`. Resource names that are not shared, especially FBOs/VAOs, remain in their creating context. Runtime chains die in private context; Cogl surfaces/effect source/FBOs die in host context; old runtime dies **before** destinations it may retain. Keep existing post-context-loss logged leak limitation rather than unsafe cross-context cleanup (`src/shader_runtime.cpp:182–209,530–590`; `waylandshader-effect.cpp:849–864`).

### 4.4 Hot data layout

Use flat `[dynamic]Output_Hot` and matching `[dynamic]Output_Cold` indexed identically, allocated/replaced only at topology changes. Callback userdata is a separate stable `{engine,key}` record reclaimed only after disconnect; no pointer to an array element survives a rebuild. Selected view lookup is a short contiguous loop; runtime stores contiguous chain rows, with no per-frame hash lookup/string conversion. Keep resources inline in separate contiguous resource storage indexed by output rather than heap-allocated Output wrappers.

Proposed `Output_Hot` order: view pointer, key uintptr, previous_time i64, first_frame i64, expanded_frame i64, gamma f64, saturation f64, resource_index u32, flags u32 = **64 bytes**; lock `#assert(size_of(Output_Hot)==64)`. Flags cache eligibility/history but status calculations still follow original meanings. `Chain_Row {key:uintptr, chain:rawptr}` =16 bytes; `#assert(size_of(Chain_Row)==16)`. Cold rows hold connector/name/failure, layout/scale, saved settings, timeline/handler ids and stable callback record. Resource arrays hold surfaces/pipelines/uniform locations/size/color-state refs and retired-resource slots; indices remain stable until explicit reconfiguration.

Do not impose a maximum monitor count. No strings/maps/JSON/status formatting, array growth or temp allocation in steady-state per-view loops. One-time GL/Cogl allocation on a new framebuffer, color state or successful preset is permitted and tested separately. Allocation tests wrap both `context.allocator` and `context.temp_allocator` with `mem.Tracking_Allocator`, warm resources first, then assert both `total_allocation_count` values unchanged across repeated selection/frame-assembly/successful paint helper loops. A real-GL repeat test additionally covers Odin runtime.render. Driver-side allocations are explicitly not measured by this allocator test. This is the required mechanical DOD guard, not a speculative performance claim.

## 8. Ranked risks, mitigations and fallback

| Rank | Risk / failure mode | Mitigation and completion gate | Allowed fallback |
|---|---|---|---|
| 1 | Wrong class/instance prefix, enum/procedure ABI, Graphene alignment corrupts Shell | Tagged field layout plus actual-SDK C probe and Odin size/offset asserts; GTypeQuery comparison; C dlopen and unchanged GJS lifecycle/recent tests before any stage attachment. | Correct Odin mirrors/bindings to measured SDK. A C subclass implementation is **not** an acceptable fallback. If exact SDK cannot be obtained, block compositor loading and report missing package, not a runnable-looking stub. |
| 2 | Odin .so runtime/export initialization or GI dumper fails, signal/method transfer metadata wrong | Keep C header, C ABI exports/context on every callback; actual scanner/dumper/headless GJS; inspect installed ELF/GIR/typelib as one artifact. | Adjust export/link/runtime flags or minimal header annotations while preserving API; do not handwrite fake GIR or retain C++ implementation. |
| 3 | EGL share policy, robust mismatch, fence publication or context restoration corrupts host/rendering | Preserve version/policy attempts, shared host, pbuffer fallback, exact saved API/surfaces and two server-side fences even after render failure; real GL3.3+normal/robust tests, host viewport/context invariant and retired destinations. | Existing 4.5/3.3 or pbuffer path only; if none works, existing error/pass-through behavior, not GLES/CPU/synchronous renderer. Actual supported AMD path must pass isolated-session before acceptance. |
| 4 | Worker/source teardown races, stale result installed, private context current on two threads | One deep-copied job, unbind before publication, GLib source attach then owner join, generation check, owner-only runtime destruction, shutdown join before source/engine free. Private-bus races and lifecycle GC plus state tests. | Repair ownership/order. Do not poll, suppress errors or move compilation onto compositor main thread. |
| 5 | GTK numeric editor silently rounds tiny parameters; chooser missing schema or accessibility/focus differs | Retain GTK3 wrapper/schema, native chooser Open/Cancel in installed app; authoritative f32 editor with native entry/buttons and bounds tests down to tiny/subnormal values, keyboard and ATK labels; no normal GtkSpinButton for shader parameter semantics. | Correct composite editor event handling, not restrict ranges/precision. GTK4 remains a consciously larger dependency alternative only if GTK3 cannot run on target and all parity tests are rerun; not a silent design change. |
| 6 | Semantic drift in settings/status/CLI/error behavior | Source-oracle fixture matrix, validate-before-commit, raw JSON preservation, MRU import/load distinction, all CLI codes including anomalous Error.Unavailable classification, availability/activation generation tests. | Match original behavior; record suspected bugs separately, no unsolicited protocol/schema fixes. |
| 7 | Odin/nixpkgs revision mismatch or custom-link RPATH fails after install | Record selected compiler/runtime versions; package-owned compiler invocation, explicit dependency paths/RPATH; scanner run and installed ELF/dependency/wrapper tests. | Select a reproducible Odin package override within the allowed dev-2026 toolchain if required and document exact revision; never pretend the independently found compiler is the package compiler. |
| 8 | Correct runtime but wrong Clutter damage/color/view behavior | Preserve source paint pipeline and clip timing; separate native output eligibility/state tests from isolated stage checks; physical limitations documented honestly. | Existing per-output bypass/raw restore on unsupported configuration. No position heuristics, screen-capture renderer or arbitrary HDR guarantee. |
| 9 | Port passes GNOME checks but damages KWin or shared patch | Keep root build and shared C++ source/fixtures untouched; root `nix-build default.nix`; private patched librashader unchanged. | Build against required KWin6.6 package set; report pre-existing version incompatibility rather than loosen ABI guards. |
| 10 | Successful headless tests mistaken for hardware/performance evidence | Label allocator scope, EGL skips and manual isolated/hardware checks; keep manual rendering/chooser acceptance unpassed until exercised. | No claimed completion for unobserved acceptance. No live-compositor experiments to close a reporting gap. |

**Smallest complete boundary:** no new features, no full binding generator, GUI design system, task pool, renderer rewrite, compatibility layer or settings migration. Build-time ABI facts, narrow FFI, plain GTK widgets and the existing algorithms are sufficient if the stated gates pass `[INFERENCE]`.

Skipped/not checked in planning: compilation, test execution, materialized SDK comparison, chooser execution and all compositor/hardware experiments. Principal release risks remain the exact Odin/Clutter ABI and cross-context GL lifetime; neither is discharged by this plan or by headless JSON tests alone.
